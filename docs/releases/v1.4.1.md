# BlackICE Panel 1.4.1

Docker installations now prepare their persistent directories automatically. Server configuration saves and bundle files remain writable when the official server creates files as root; permission repair is scoped to the owned server mount and the Supervisor stays UID 10001.

The panel updater now supports Docker. It verifies the Linux release package using GitHub's SHA-256 digest, stores the selected runtime in persistent panel state, restarts only the two panel services and checks readiness. A startup failure restores the previous runtime. Game files, configuration, networks, container identities and deployment definitions are retained. The game stays running during panel updates. Docker base-image/OS upgrades remain deployment operations.

- Docker startup finds the frontend without a manual working-directory override.
- `keep-running` now applies to Docker Supervisor restarts as well as Webhost restarts.
- Commands reconnect after an external game restart instead of writing to a stale console attachment.
- Panel-managed game startup preserves `server.settings.json` rather than overwriting dashboard edits from image environment variables.
- The standalone Docker bundle includes its image, Compose file, version and startup script. Extract it and run `sh scripts/docker.sh`; no registry login or manual chmod is required.

Existing Docker deployments must adopt the included entrypoint, role labels and `REPLAY_PANEL_DOCKER_UPDATES=1` once before dashboard panel installation is available. Access still requires settings-write and user-management permissions; these changes do not grant anonymous access or broaden account permissions.
