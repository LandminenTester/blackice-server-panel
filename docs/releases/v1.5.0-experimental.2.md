This second experimental preview makes Bundle Tools easier to use for teams developing locally and testing their changes on a server. Projects now have a compact overview and a dedicated details workspace. Remote branches can be compared and merged through the configured Git provider, while package updates are proposed through review requests without changing the active checkout.

The bundle list and settings have also been reorganized, with clearer controls, searchable selections and more granular permissions. Bundle Tools remain optional and disabled by default.

### Projects and Git workflows

- Replace the development-to-production screen with **Merge branches**: select source and target from searchable remote-branch dropdowns and inspect commits and changed files before proceeding.
- Add global review-request/direct-merge policies with per-project overrides. Review requests remain the default; direct merges require a separate permission and confirmation.
- Recheck branch commit identities before merging, respect provider protections and report unconfirmed results without automatically repeating writes. Deployment remains a separate action.
- Add account-based repository discovery and searchable owner/repository selections, including supported organizations and groups.
- Move NuGet management into a dedicated dialog showing installed and latest common versions, with optional specific-version and prerelease selection.
- Propose package changes in an isolated checkout, push a change branch and create a review request; leave active sources and installed bundles unchanged.
- Add framework-specific state choices and working examples: Zustand/Jotai/Nano Stores for React, Pinia/Nano Stores for Vue, and local/shared runes or Nano Stores for Svelte.

### Bundle management

- Add searchable bundle lists and persistent category tags with category filtering.
- Add reversible autostart control for supported static startup configurations, including included files, backups and reconciliation before managed startup.
- Add scoped bundle deletion with a confirmed stop and separate permissions for deleting sources or eligible local persistent data. Data is preserved by default.
- Recheck ZIP target names before installation and show an explicit overwrite-or-cancel dialog for existing bundles.

### Interface and localization

- Split Bundle Tools settings into General, Build tools and Git accounts subtabs.
- Refine project rows, consistent branch/commit/Web-UI badges and inline last-build timestamps and status.
- Reorganize creation/import dialogs into compact two-column layouts; keep repository fields visible but disabled when unused.
- Improve build-job output with search, follow, pause/resume and download controls.
- Refine the bundle filter toolbar with a search icon, consistent control heights, interior spacing and responsive timestamp placement.
- Shorten and reposition the experimental indicator, improve account-label spacing and rename the account edit action appropriately.
- Clarify English/German merge, package and status terminology; fix the malformed dash in last-build text and add automated locale/reference/encoding checks.

### Tool detection and security

- Detect installed host Git, .NET SDK 10, Node.js/npm and existing WASI SDK caches alongside optional panel-managed tool copies.
- Add separate server-side permissions for review requests, direct merges, package proposals, categories, autostart and deletion scopes; group permissions in user administration.
- Bind saved provider credentials to their configured destination and prevent authenticated redirects.
- Harden outbound HTTP destination checks for provider, installer and update requests with public-address validation and DNS-pinned connections.
- Strengthen bundle/source path and symlink checks and expand regression coverage for denied HTTP actions and bundle lifecycle operations.
- Update English/German documentation for shared server accounts, development workflows and the limits of build permissions.

### Upgrade and experimental limitations

Choose the **experimental update channel** to receive this preview. Existing configuration and server data are retained. Windows and Linux native packages, a versioned Docker image/export and SHA-256 checksums are provided by the release pipeline after its checks pass.

Build permission allows project code to execute with the panel OS account's rights; it is not a sandbox. Console write access is similarly powerful. Use trusted sources and dedicated repository-scoped provider tokens, isolate development from production and read [SECURITY.md](https://github.com/LandminenTester/blackice-server-panel/blob/experimental/SECURITY.md). This release does not claim an independent security audit. Provider merge protection may leave an open review request when a direct merge is refused; inspect the returned link before retrying.
